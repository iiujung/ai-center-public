# kb-setup：從零開始的基礎訪談

## 規矩
- 問題**一個一個問**，老闆答完一題再問下一題；老闆說「跳過」就留「（待填）」，不替老闆編。
- 問完先用幾句話複述理解和建庫計畫（改哪些名字、填哪些檔、建哪些員工），老闆說「可以」才動手。
- 只在 `~/AI-Center/ai-company` 和 `~/AI-Center/` 底下那幾個 repo 外資料夾裡寫檔。
- 遇到要輸密碼、要授權或系統跳窗，停下來告訴老闆要點什麼，等老闆說「好了」再繼續。

## 步驟

### 1. 先讀骨架
讀 `~/AI-Center/ai-company/AGENTS.md`、`公司1/AGENTS.md`、`個人1/AGENTS.md` 和 `角色/AGENTS.md`，知道有哪些「（待填）」。

### 2. 訪談（一題一題問）
1. **你是誰**：怎麼稱呼、做什麼、喜歡別人怎麼跟你說話、有什麼忌諱。
2. **要建哪幾家**：只要正職（`公司1`）、只要個人生活與自媒體（`個人1`），還是兩家都要、或更多家。每家取一個英文或拼音短名（小寫、數字、連字符，例如 `work-acme`、`life-studio`）。
3. **每一家做什麼**：目標是什麼、主要做哪幾項業務（每項會在 `業務/` 底下開一個資料夾）。兩家以上就一家一家問。
4. **給誰看、怎麼說話**：受眾是誰、口吻；視覺風格有就說，沒有就留空。
5. **用哪些 AI 工具**：預設是 Claude 桌面版；還有沒有用 Codex、Gemini 等其他家。可以幫老闆跑 `claude --version`、`codex --version`、`gemini --version` 確認裝了沒。
6. **要哪些員工**：骨架預設總經理 `gm`、助理 `assistant`、研究員 `researcher`。依第 3 題的業務建議加哪些（例如寫文案的 `content`、做設計的 `designer`、寫程式的 `dev`），老闆決定；用不到的預設員工可以刪。
7. **有沒有不能上雲端的資料**：例如朋友的私訊、公司機密，決定放哪（`~/AI-Center/<短名>-private/`）、哪些不進 git。

### 3. 複述計畫，等「可以」

### 4. 動手
1. 不要的公司：刪掉那家資料夾和 repo 外對應的資料夾，`~/AI-Center/ai-company/AGENTS.md` 和 `README.md` 的表格跟著刪。
2. 改名：照 `kb-migrate` 的第 4 步（`mv` 資料夾、把所有寫死的 `公司1`／`個人1` 換成新名字、repo 外資料夾一起改名）。
3. 填檔：第 1 題寫進 `主理人/基本資料.md`；第 3、4 題寫進 `品牌/品牌基礎.md`；各公司總規矩的「老闆和公司」兩段也填上；`~/AI-Center/ai-company/AGENTS.md` 和 `README.md` 的「（待填）」一起填。
4. 業務：在 `業務/` 底下每項業務建一個資料夾（英文或拼音短名），`業務/AGENTS.md` 的「目前的業務」列出來。
5. 員工：照 `角色/AGENTS.md` 的「新建崗位的做法」建新員工、刪不要的；名冊的「用哪家」照第 5 題填，只有 Claude 就全部寫 `claude`。
6. 第 7 題的答案寫進總規矩「底線」。
7. 更新每家的 `指引目錄.md`：一句話介紹、員工表、「我想做……該怎麼說」。

### 5. 檢查
照 `kb-migrate` 的第 6 步：量位元組數（總規矩 ≤ 9000、資料夾說明 ≤ 3000、崗位手冊 ≤ 4000）、找斷掉的連結、列出還沒填的「（待填）」。

### 6. 回報老闆
- 每家公司的名字和完整路徑、改了哪些檔（可點的 markdown 連結）。
- 員工名冊。
- 還留著「（待填）」的地方。
- 下一步：照 `~/AI-Center/使用說明.md` 的「讓員工上崗」請總經理上崗；要跨電腦同步就在 `~/AI-Center/ai-company` 裡 `git init` 並推上私人 GitHub repo。
