# kb-migrate：把舊知識庫搬進這套骨架

老闆已經有自己的知識庫，不用重新訪談；從舊資料裡找答案，填進骨架的「（待填）」。

## 規矩
- 舊資料**只讀**：複製過來（`cp`），不搬走、不改、不刪原本的檔。
- 只在 `~/AI-Center/ai-company` 和 `~/AI-Center/` 底下那幾個 repo 外資料夾裡寫檔。
- 動手前先給老闆看對照表，等老闆說「可以」。
- 舊資料裡的密碼、金鑰：**不複製內容**，只在回報裡提醒老闆「某檔有金鑰，請自己放進 `~/AI-Center/ai-company/.env`」。
- 看不出該放哪的，問老闆；老闆也說不準的，放 `收件箱/`（檔名前加今天的八位日期）。
- 舊資料裡沒寫的項目，「（待填）」照樣留著，不替老闆編。

## 步驟

### 1. 問三件事（一個一個問）
1. 舊知識庫在哪：完整路徑，可以不只一個。
2. 要搬進哪一家：`公司1`（正職）、`個人1`（生活與自媒體），還是新加一家。
3. 新名字：英文或拼音短名，小寫、數字、連字符，例如 `life-studio`、`work-acme`。

### 2. 讀骨架，再盤點舊資料
- 先讀 `~/AI-Center/ai-company/AGENTS.md`、那家公司的 `AGENTS.md`，和九個資料夾各自的 `AGENTS.md`。
- 列出舊資料的檔案清單（`find <舊路徑> -type f -not -path '*/.git/*' | head -500`），太多就先看資料夾結構再抽樣讀。

### 3. 做對照表給老闆看
一行一個「舊檔或舊資料夾 → 新位置 → 怎麼處理（照搬／合併進某檔／摘要填進某欄／放收件箱／不搬）」。常見對應：

| 舊資料裡的 | 搬到 |
|---|---|
| 自我介紹、偏好、說話風格、忌諱、被糾正過的事 | `主理人/`（填進 `基本資料.md`，其餘一個主題一個檔） |
| 定位、受眾、口吻、視覺規範 | `品牌/`（填進 `品牌基礎.md`） |
| 收入、合作、新機會 | `商業/` |
| 正在做的專案、發出去的成品 | `業務/<業務短名>/` |
| 工具用法、設定、踩過的坑 | `工具/最佳實踐/` |
| Skill、prompt 範本、可重複的流程 | `~/AI-Center/ai-company/共用/工具/技能/<名字>/SKILL.md`，再掛連結 |
| 查來的資料、讀書筆記 | `研究/`（檔名 `<八位日期>-<主題>.md`） |
| AI 員工的設定、system prompt、崗位說明 | `角色/<英文名>/AGENTS.md`，改寫成本骨架的五件事格式 |
| 進行中的待辦、草稿 | `工作看板/任務/` |
| 舊的、用不到的 | `收件箱/` |
| 影片、錄音、大圖 | `~/AI-Center/<新名字>-big-files/` |
| 不適合上雲端的私人資料 | `~/AI-Center/<新名字>-private/` |

同時列出：要改的名字（`公司1` → 新名字）、要新建或刪掉的崗位、要搬的 Skill。等老闆說「可以」。

### 4. 改名
在 `~/AI-Center/ai-company` 執行（Mac）：
```bash
mv 公司1 <新名字>
grep -rlI --exclude-dir=.git '公司1' . | xargs sed -i '' 's/公司1/<新名字>/g'
```
repo 外的資料夾也一起改名（`~/AI-Center/公司1-big-files` 等）。Skill 連結是相對路徑，改公司名不會斷。

### 5. 搬
- 照對照表複製、整理；摘要類的填進對應檔的「（待填）」。
- 崗位：舊的 AI 員工照 `角色/AGENTS.md` 的「新建崗位的做法」建；骨架預設的 `assistant`、`researcher` 用不到就刪掉資料夾，總規矩名冊和 `角色/AGENTS.md` 一起改。
- Skill：放進共用層，在這家公司的 `.claude/skills/`、`.agents/skills/` 掛連結（做法見 `~/AI-Center/ai-company/共用/AGENTS.md`）。
- 舊知識庫有自己的「業務」資料夾名（例如 `內容營運/`、`產品營運/`），可以把 `業務/` 改成那個名字，總規矩和指引目錄裡的引用一起改。
- 最後更新那家公司的 `指引目錄.md`。

### 6. 檢查
```bash
cd ~/AI-Center/ai-company
wc -c AGENTS.md */AGENTS.md */*/AGENTS.md */角色/*/AGENTS.md   # 總規矩 ≤ 9000，資料夾說明 ≤ 3000，崗位手冊 ≤ 4000
find . -type l ! -exec test -e {} \; -print                     # 斷掉的連結，應該沒有輸出
grep -rn '（待填）' --include='*.md' .                           # 還沒填的項目
```

### 7. 回報老闆
- 搬了什麼、放在哪（可點的 markdown 連結）。
- 沒搬的和原因；放進收件箱的清單。
- 還留著「（待填）」的地方，問老闆要不要現在補。
- 需要老闆自己處理的：金鑰放進 `.env`、私人資料確認、要不要 `git init` 並推上私人 GitHub repo。
- 下一步：照 `~/AI-Center/使用說明.md` 的「讓員工上崗」請總經理上崗。
