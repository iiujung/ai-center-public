# AI-Center 架構空殼

> **參考來源**：這套架構參考 YouTube 頻道 [翔宇工作流](https://www.youtube.com/@xiangyugongzuoliu) 的影片〈[Herdr 實戰：從零搭建 AI 一人公司，用 Claude Code、Codex 組建 AI 員工團隊](https://www.youtube.com/watch?v=soT6SuYzHiY)〉的做法：用一個資料夾當公司知識庫、九個根目錄分類、每位 AI 員工一份手冊、任務卡派工、`AGENTS.md` 加軟連結讓各家 AI 共讀。
>
> 我實際用了一陣子後改良成這個版本：
> - 多一層 `AI-Center/`，一個 repo 放好幾家公司（正職、個人生活與自媒體各一家），彼此隔離。
> - Skill 抽到共用層 `共用/工具/技能/`，各公司用軟連結共用，金鑰也只放一份。
> - 主力改用 Claude 桌面版（一位員工一個 session），不一定要裝 Herdr。
> - 分成「從零開始」和「已經有知識庫要搬」兩種情境，各有一個 Skill 帶著走。
> - 用語改成台灣繁體中文。

一套用資料夾當 AI 員工知識庫的架構：一個 repo 裡放幾家彼此獨立的「公司」，加一層大家共用的 Skill。這份是**空殼**：骨架、規矩、說明檔都寫好了，內容留著「（待填）」，給**已經有自己知識庫**的人直接搬進來用，不用重新做訪談。

## 長什麼樣

```
~/AI-Center/                     ← 這個資料夾改名成 AI-Center 放到家目錄
├── ai-company/                  ← 唯一的 git repo
│   ├── AGENTS.md                ← 共用總則（CLAUDE.md、GEMINI.md 是指向它的軟連結）
│   ├── .env                     ← 金鑰只有這一份，不進 git（照 .env.example 自己建）
│   ├── 共用/工具/技能/           ← 所有 Skill 的實體，各公司用軟連結叫用
│   ├── 公司1/                   ← 範例：正職工作
│   └── 個人1/                   ← 範例：生活與自媒體
├── 公司1-big-files/             ← 公司1 的大檔（不進 git）
├── 個人1-big-files/             ← 個人1 的大檔（不進 git）
└── 個人1-private/               ← 不適合上雲端的資料（只在本機）
```

每家公司裡面都是同一套九個資料夾，按幾個最簡單的問題分：

| 問題 | 資料夾 |
|---|---|
| 我是誰 | `主理人/`、`品牌/` |
| 我做什麼 | `商業/`、`業務/` |
| 我怎麼做 | `工具/`（Skill 在共用層）、`研究/` |
| 誰來做 | `角色/`（每位 AI 員工一份手冊和工作記錄） |
| 做到哪了 | `工作看板/`（任務卡和草稿） |
| 過期的 | `收件箱/` |

每個資料夾都有一份 `AGENTS.md` 說明放什麼、不放什麼、怎麼命名；旁邊的 `CLAUDE.md`、`GEMINI.md` 是指向它的軟連結，所以 Claude Code、Codex、Gemini 等各家 AI 都讀得到同一份。

## 怎麼用

1. 把這個 repo 下載到家目錄的 `AI-Center`（已經有 `~/AI-Center` 的，先 clone 到別處，再把裡面的東西搬進去）。
   ```bash
   git clone https://github.com/iiujung/ai-center-public.git ~/AI-Center
   rm -rf ~/AI-Center/.git   # 斷開和這個公開範本的連結，之後在 ai-company/ 裡建你自己的私人 repo
   ```
2. 在 Claude 桌面版（Code 分頁）開一個 session，資料夾選 `~/AI-Center/ai-company`，依情況貼一句：

   | 情境 | 貼這句 | 會發生什麼 |
   |---|---|---|
   | **從零開始**，手上沒有知識庫 | `用 kb-setup 幫我從零開始建知識庫。` | 一題一題做基礎訪談，填好骨架、改好名字、建好員工 |
   | **已經有知識庫**，要搬進來 | `用 kb-migrate 把我的知識庫 <舊資料夾完整路徑> 搬進 個人1，新名字叫 <英文短名>。` | 先列「舊檔 → 新位置」對照表給你看，說「可以」才搬；舊資料只複製不改 |

3. 照 `ai-company/.env.example` 建一份 `ai-company/.env` 放金鑰。
4. 請總經理上崗，之後只跟它說話。
5. 想跨電腦同步，在 `ai-company/` 裡 `git init`、推到自己的私人 GitHub repo。

**完整步驟、怎麼讓員工上崗、怎麼派工、這套架構的優勢和重點，看 [使用說明.md](使用說明.md)。**

## AI-Center 解決了哪三個痛點

每次用 AI 做東西，最常卡住的是那種「不確定感」：Skill 越收越多卻管不動、換一家 AI 就要重來、聊完的東西不知道該放哪。這套架構就是針對這三件事。

### 1. Skill 統一管理，每個專案只拿自己要的

**痛點**：每個專案都有自己的 Skill，散在各處沒辦法統一管理；可是全部塞在一起，Skill 一多，AI 反而不知道該用哪個，效率變差。

**做法**：Skill 的實體全部集中在一個 Skill 庫 `共用/工具/技能/`，只放一份。每家公司（每個工作區）再用「軟連結」挑自己要用的：

```
共用/工具/技能/              ← Skill 庫：所有 Skill 只有這一份（以下 Skill 名稱是示意）
├── image-gen/
├── seo-writing/
├── voice-polish/
└── research/

公司1/.claude/skills/        ← 公司1 只掛它用得到的
├── seo-writing  → 連到 Skill 庫
└── research     → 連到 Skill 庫

個人1/.claude/skills/        ← 個人1 掛另一組
├── image-gen    → 連到 Skill 庫
├── voice-polish → 連到 Skill 庫
└── research     → 連到 Skill 庫（同一份，兩邊共用）
```

- **軟連結**就像桌面捷徑：看起來是一個資料夾，打開其實是 Skill 庫裡那一份。
- 每家公司的 `.claude/skills/` 本身就是一張「這個工作區用哪些 Skill」的清單；想知道某家用了什麼，看這個資料夾就好。
- AI 在某家公司開工時，只會看到那家掛了連結的 Skill，不相干的不會出來搶戲；而且平常只讀每個 Skill 的名字和一句說明，真的用到才讀全文，掛得多也不太佔記憶。
- 改一個 Skill 只改 Skill 庫那一份，所有掛了連結的公司同時生效。

結果就是**相乘**：Skill 庫可以一直長大、統一管理，每個專案又能依自己的業務情境和流程，組出自己的一套。

### 2. 同一套 Skill 和規矩，跨 AI 工具都能用

**痛點**：在 Claude 寫好的 Skill 和規矩，換到 Codex、Gemini 就讀不到，要重寫一份。

**原理**：
- **Skill 的格式是共通的**：一個資料夾，裡面一份 `SKILL.md`，開頭寫名字和什麼時候用。這個格式現在是 Agent Skills 開放標準，Claude 以外的多家 AI 工具也採用，所以同一份 Skill 各家都看得懂。
- **只是各家去不同的地方找**：Claude 找 `.claude/skills/`，Codex 等其他工具找 `.agents/skills/`。所以同一個 Skill 在兩個地方各掛一個軟連結，指回 Skill 庫的同一份，各家都找得到，內容永遠一致。
- **規矩也是同一招**：各家 AI 開工會自動讀的檔名不一樣（Claude 讀 `CLAUDE.md`、Gemini 讀 `GEMINI.md`、Codex 等讀 `AGENTS.md`）。這裡只寫 `AGENTS.md` 一份正本，另外兩個檔名用軟連結指過去，改一處，各家一起更新。Windows 建不了軟連結時，改成只寫一行 `@AGENTS.md` 的普通檔案。

這招是原作者的做法，所以換工具時，只要改員工名冊裡「用哪家」那一欄，手冊和 Skill 都不用動。各家實際讀哪個檔、找哪個資料夾，會隨版本更新，以各家官方文件為準。

### 3. 放心跟 AI 聊，東西會自己歸檔

**痛點**：跟 AI 討論完，產出散落各處，下次找不到，也不知道該放哪。

**做法**：每個資料夾都有一份 `AGENTS.md`，寫清楚「這裡放什麼、不放什麼（該去哪）、檔名怎麼取」。總規矩也規定：要往哪個資料夾放東西之前，先讀那個資料夾的說明。所以你只管討論，草稿會進 `工作看板/任務/`、查來的資料進 `研究/`、定案的成品進 `業務/`，AI 自己判斷放對地方。

### 其他設計

- **公司彼此隔離**：正職和個人生活的資料各放各的，AI 不跨公司讀檔，除非你明說；Skill 庫和金鑰則各家共用一份。
- **說明檔寫短**：總規矩不超過 9000 位元組、各資料夾說明不超過 3000、崗位手冊不超過 4000。AI 每次開工都要讀，太長會吃掉它的記憶空間。
