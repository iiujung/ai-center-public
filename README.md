# AI-Center 架構空殼

> **參考來源**：這套架構參考 YouTube 頻道 [翔宇工作流](https://www.youtube.com/@xiangyugongzuoliu) 的影片〈[Herdr 實戰：從零搭建 AI 一人公司，用 Claude Code、Codex 組建 AI 員工團隊](https://www.youtube.com/watch?v=soT6SuYzHiY)〉的做法：用一個資料夾當公司知識庫、九個根目錄分類、每位 AI 員工一份手冊、任務卡派工、`AGENTS.md` 加軟連結讓各家 AI 共讀。
>
> 我實際用了一陣子後改良成這個版本：
> - 多一層 `AI-Center/`，一個 repo 放好幾家公司（正職、個人生活與自媒體各一家），彼此隔離。
> - Skill 抽到共用層 `共用/工具/技能/`，各公司用軟連結共用，金鑰也只放一份。
> - 主力改用 Claude 桌面版（一位員工一個 session），不一定要裝 Herdr。
> - 分成「從零開始」和「已經有知識庫要搬」兩種情境，各有一個 Skill 帶著走。
> - 用語改成台灣繁體中文。

一套用資料夾當 AI 員工知識庫的架構：一個 repo 裡放幾家彼此獨立的「公司」，加一層大家共用的 Skill。這份是**空殼**：骨架、規矩、說明檔都寫好了，內容留著「（待填）」，給**已經有自己知識庫**的人直接搬進來用，不用重新做訪談。

## 長什麼樣

```
~/AI-Center/                     ← 這個資料夾改名成 AI-Center 放到家目錄
├── ai-company/                  ← 唯一的 git repo
│   ├── AGENTS.md                ← 共用總則（CLAUDE.md、GEMINI.md 是指向它的軟連結）
│   ├── .env                     ← 金鑰只有這一份，不進 git（照 .env.example 自己建）
│   ├── 共用/工具/技能/           ← 所有 Skill 的實體，各公司用軟連結叫用
│   ├── 公司1/                   ← 範例：正職工作
│   └── 個人1/                   ← 範例：生活與自媒體
├── 公司1-big-files/             ← 公司1 的大檔（不進 git）
├── 個人1-big-files/             ← 個人1 的大檔（不進 git）
└── 個人1-private/               ← 不適合上雲端的資料（只在本機）
```

每家公司裡面都是同一套九個資料夾，按幾個最簡單的問題分：

| 問題 | 資料夾 |
|---|---|
| 我是誰 | `主理人/`、`品牌/` |
| 我做什麼 | `商業/`、`業務/` |
| 我怎麼做 | `工具/`（Skill 在共用層）、`研究/` |
| 誰來做 | `角色/`（每位 AI 員工一份手冊和工作記錄） |
| 做到哪了 | `工作看板/`（任務卡和草稿） |
| 過期的 | `收件箱/` |

每個資料夾都有一份 `AGENTS.md` 說明放什麼、不放什麼、怎麼命名；旁邊的 `CLAUDE.md`、`GEMINI.md` 是指向它的軟連結，所以 Claude Code、Codex、Gemini 等各家 AI 都讀得到同一份。

## 怎麼用

1. 把這個資料夾複製到家目錄，改名成 `AI-Center`（已經有 `~/AI-Center` 的，就只把裡面的東西搬進去）。
   ```bash
   cp -R ai-center-template ~/AI-Center
   ```
2. 在 Claude 桌面版（Code 分頁）開一個 session，資料夾選 `~/AI-Center/ai-company`，依情況貼一句：

   | 情境 | 貼這句 | 會發生什麼 |
   |---|---|---|
   | **從零開始**，手上沒有知識庫 | `用 kb-setup 幫我從零開始建知識庫。` | 一題一題做基礎訪談，填好骨架、改好名字、建好員工 |
   | **已經有知識庫**，要搬進來 | `用 kb-migrate 把我的知識庫 <舊資料夾完整路徑> 搬進 個人1，新名字叫 <英文短名>。` | 先列「舊檔 → 新位置」對照表給你看，說「可以」才搬；舊資料只複製不改 |

3. 照 `ai-company/.env.example` 建一份 `ai-company/.env` 放金鑰。
4. 請總經理上崗，之後只跟它說話。
5. 想跨電腦同步，在 `ai-company/` 裡 `git init`、推到自己的私人 GitHub repo。

**完整步驟、怎麼讓員工上崗、怎麼派工、這套架構的優勢和重點，看 [使用說明.md](使用說明.md)。**

## 幾個設計上的選擇

- **一份正本，各家 AI 共用**：說明檔只寫 `AGENTS.md`，`CLAUDE.md`、`GEMINI.md` 用軟連結指過去，改一處全部生效。Windows 建不了軟連結時，改成兩個只寫一行 `@AGENTS.md` 的普通檔案。
- **Skill 只有一份實體**：放 `共用/工具/技能/<名字>/`，哪家公司要用就在那家的 `.claude/skills/`、`.agents/skills/` 掛相對路徑軟連結，整個資料夾搬家也不會斷。
- **公司彼此隔離**：正職和個人生活的資料各放各的，AI 不跨公司讀檔，除非你明說。
- **說明檔寫短**：總規矩不超過 9000 位元組、各資料夾說明不超過 3000、崗位手冊不超過 4000，AI 每次開工都要讀，太長會吃掉上下文。
